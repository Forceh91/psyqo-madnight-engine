# Tech demo

One scene that uses most of the engine at once, so it doubles as a regression and performance check: a long stone hall under advanced fog, a skinned character walking into the fog and back with quick advanced fog, two particle emitters, trigger volumes that turn the character round, a pause menu (Start) and a memory card save of the last lap's numbers.

Sound: `FCNTNA.VAG` loops as background music and `AMBIENT_CREAK.VAG` plays every 600 vsyncs. Both come from Supermarket Sweep and are used with its owner's permission. On start the scene reads the last save from slot 1, if there is one, and shows it at the bottom of the screen.

The camera follows a fixed path keyed to elapsed vsyncs, so every lap draws the same frames. The bottom of the screen shows how many vsyncs the last frame took and, after each lap, the lap's average and worst.

## Building

The demo builds against the engine checkout it sits in.

```
make -C tech-demo DEFINES=PCDRV
make -C tech-demo image
```

`make image` writes `build/techdemo.bin`, which a PCDRV build reads from the host:

```
pcsx-redux -pcdrv -pcdrvbase "$PWD/tech-demo/build" -run -loadexe "$PWD/tech-demo/tech-demo.ps-exe"
```

The paths are absolute because the emulator resolves them against its own working directory, which on macOS `open -a PCSX-Redux --args ...` sets to `/`.

For a real disc, build without `DEFINES=PCDRV` and run pcsx-redux's [authoring tool](https://github.com/grumpycoders/pcsx-redux/tree/main/tools/authoring) on `toc.json` from this directory: `authoring -o techdemo.bin toc.json`.

Switching between a PCDRV and a disc build needs a `make -C tech-demo clean` first, because the engine library is built with the same define.

## Bench mode

`make -C tech-demo DEFINES=PCDRV BENCH=1` runs one lap, prints `TECHDEMO lap=...` with the frame count and vsyncs, saves the numbers to the card in slot 1, reads them back and exits the emulator (under `-testmode`). CI runs it this way and fails if the card read-back does not match.

## Assets

Everything in `assets/` is generated by `tools/make_assets.py` (Python 3 with numpy and Pillow): the meshes go through `tools/obj-to-meshbin.py`, the textures through `tools/tim_creator.py` and the manifest through `tools/scenebin_converter.py`. Only the walk cycle is written directly, since the animation exporter runs inside Blender. Run it again after changing it and commit the output.
